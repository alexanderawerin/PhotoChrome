# Проверка AAC, геометрии и реальных устройств

Эта процедура описывает, как собрать оставшиеся доказательства для issues #8, #11, #13 и родительского #4. Публикация на прод запрещена. Прогоны ниже локальные: они не запускают GitHub Actions и не содержат шагов деплоя.

Приложение уже реализовано в merge `975357b` ([PR #16](https://github.com/alexanderawerin/PhotoChrome/pull/16)). Ветка `codex/audio-device-acceptance-2026-10-01` добавляет контрольный AV-файл, совместную проверку звука/геометрии и эту инструкцию; продуктовый код не меняется.

## Что нужно подтвердить

| Issue | Оставшееся доказательство |
| --- | --- |
| #8 | Настоящий AAC экспорт: действительная дорожка, исходный сигнал, начало/конец и синхронизация. |
| #11 | Один MP4 с одновременно применённой геометрией и сохранённым звуком: размеры/пиксели, video PTS/durations и отсутствие смещения/дрейфа между вспышками и звуковыми метками. |
| #13 | Firefox, настоящий Safari/macOS и реальные iPhone/Android: фото, video capabilities, геометрия/звук, отмена/восстановление и управление. |
| #4 | Полная приёмка после подтверждения перечисленных пунктов. |

Успешная сборка, наличие скачивания или общий зелёный результат со skipped AAC не подтверждают сохранение звука. Playwright WebKit не подтверждает поведение настоящего Safari; mobile viewport не заменяет телефон.

## Контрольные файлы

- `e2e/fixtures/test-image.jpg` и `test-image-2.jpg`: фото и переключение между независимыми правками.
- `e2e/fixtures/test-video.mp4`: 3 секунды, 640×360, 30 FPS, AAC 48 kHz mono, непрерывный сигнал 440 Hz.
- `e2e/fixtures/test-video-offset-audio.mp4`: 3 секунды и звук с исходным смещением; для сравнения timestamps дорожки.
- `e2e/fixtures/test-video-asymmetric-audio.mp4`: 320×180, 24 FPS, 51 кадр / 2,125 секунды. Асимметричные цветные области и белые вспышки со звуковыми импульсами в окнах 0,500–0,625 и 1,833333–1,958333 s. AAC 48 kHz mono начинается со смещением около 0,4 s; фактические packet/sample timestamps сравниваются с источником, учитывая AAC priming.
- В скачиваемом архиве `photochrome-device-acceptance.zip` для ручной проверки есть `test-video-cancel-25s.mp4`: 25 секунд, 640×360 / 30 FPS со звуком. Он нужен для отмены, а не для оценки универсального предела памяти.

Не регенерируйте фикстуры на проверяемом устройстве: используйте поставленные файлы.

## Автоматическая проверка на Mac

Нужны Node.js 22, `ffmpeg`, установленный Google Chrome и свободный localhost:5173. Завершите свой старый dev-сервер перед прогоном, чтобы тесты открыли именно новый checkout. Этот прогон запускает официальный Chrome, потому что Linux Chromium не подтвердил необходимую конфигурацию AAC. Реальная поддержка всё равно проверяется в самом тесте.

Если `ffmpeg` отсутствует и на Mac установлен Homebrew, его можно установить командой `brew install ffmpeg`.

Создайте отдельный checkout, чтобы сохранить существующую рабочую копию:

```sh
git clone --single-branch --branch codex/audio-device-acceptance-2026-10-01 https://github.com/alexanderawerin/PhotoChrome.git PhotoChrome-acceptance
cd PhotoChrome-acceptance
node --version
npm ci
mkdir -p /tmp/photochrome-acceptance
git rev-parse HEAD > /tmp/photochrome-acceptance/revision.txt
sw_vers > /tmp/photochrome-acceptance/macos.txt
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --version > /tmp/photochrome-acceptance/chrome-version.txt
```

Запустите настоящие экспорты и проверку скачанных файлов:

```sh
env -u CI PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" PLAYWRIGHT_JSON_OUTPUT_FILE=/tmp/photochrome-acceptance/chrome.json npx playwright test e2e/video-export.spec.ts e2e/video-geometry.spec.ts --project=chromium --workers=1 --reporter=line,json --output=/tmp/photochrome-acceptance/chrome-artifacts
```

Для закрытия AAC нужны **PASS**, а не SKIP, у теста `supported AAC retains the source audio offset and end time` и `supported AAC stays synchronized after rotation, reflection and square crop`. Тест обычного видео должен выполнить положительную проверку сигнала 440 Hz. Если probe сообщает unsupported, сохраните отчёт: это открытая проверка, а не подтверждение сохранённого звука.

Firefox проверяется отдельно:

```sh
npx playwright install firefox
env -u CI PLAYWRIGHT_JSON_OUTPUT_FILE=/tmp/photochrome-acceptance/firefox.json npx playwright test --project=firefox --workers=1 --reporter=line,json --output=/tmp/photochrome-acceptance/firefox-artifacts
```

Этот Firefox-прогон проверяет собственные сценарии Gecko. Пропуски Chromium-only видео-тестов не подтверждают экспорт в Firefox: его фактическое поведение входит в ручную проверку ниже.

Соберите результаты без node_modules и пользовательских исходных фото:

```sh
tar -czf /tmp/photochrome-acceptance-results.tar.gz -C /tmp photochrome-acceptance
```

Для анализа нужны этот архив, фактические MP4 из artifacts и сообщения о любых ошибках. Если зависимость или браузер не установились, сохраните текст ошибки; соответствующая проверка остаётся открытой.

## Ручная проверка

Скачайте `photochrome-device-acceptance.zip` из сообщения с результатами подготовки и распакуйте. Передайте контрольные файлы на телефоны, например через AirDrop или облачную папку. `RESULTS.md` в архиве содержит таблицу для записи результатов.

Используйте [приватную проверочную сборку PR #16](https://photochrome-pr16-review.alexanderawerin1976.chatgpt.site). Её продуктовый код совпадает с проверяемым merge `975357b`; новый regression test не изменяет сайт. Авторизуйтесь своей учётной записью ChatGPT. Не открывайте прод-домен для этой приёмки.

Пройдите таблицу в настоящем Safari на Mac, Safari на iPhone и Chrome на Android. На телефонах повторите основные действия в portrait и landscape. Дополнительно проверьте export/capability feedback в обычном Firefox.

| Проверка | Действия и ожидаемый результат |
| --- | --- |
| Фото и Advanced | Добавьте оба фото. Выберите фильм, в Advanced измените Manual, отмените: applied результат возвращается. Повторите и примените: правка сохраняется. Переключение фото сохраняет независимые правки. JPEG соответствует applied результату. Повторите загрузку и экспорт на одном-двух обычных снимках с камеры, например 12 MP, в пределах существующих лимитов. |
| Видео: обратимая геометрия | Откройте асимметричный AV-клип. Поверните по часовой стрелке и отразите горизонтально: 180×320. Откройте Crop и выберите 1:1, затем Cancel: сохраняется 180×320. Повторите и Apply: 180×180. Выбор фильма и возврат к Original сохраняют композицию. Размеры здесь относятся к композиции и экспортированному MP4: информационный badge видео продолжает показывать исходные размеры. |
| Совместный экспорт | Оставьте Original и applied 1:1 после rotate+flip. Экспортируйте MP4. При поддержке звука ожидаются 180×180, 51 кадр, исходный video timing и два синхронных импульса/вспышки. Сохраните настоящий файл и воспроизведите его вне приложения. Для подтверждения timing файл анализируется автоматически; прослушивания недостаточно. |
| Возможности браузера | Если звук сохранить нельзя, требуется явный Export without sound. Закройте/отмените это предложение: скачивания нет. Явное согласие даёт файл без аудиодорожки. Если видеоэкспорт не поддерживается, ожидается понятная ошибка и доступное редактирование; запишите точный текст. |
| Отмена и повтор | На 25-секундном клипе начните экспорт и отмените до доставки. Поздний файл не появляется. Повторите экспорт. После завершения замените media; предыдущий запрос не возобновляется, управление не зависает. Если экспорт завершился раньше отмены, отметьте этот сценарий UNTESTED и повторите с более тяжёлым допустимым клипом. |
| Compare и доступность | Снова выберите фильм после Original, чтобы результат отличался. Удерживайте compare и отпустите: возвращается обработанное изображение без смены геометрии/позиции видео. На телефоне проверьте отпускание после жеста и смены ориентации. На desktop проверьте клавиатуру/Escape и увеличенный текст/масштаб 200%; действия остаются видны и достижимы. |
| Повторное использование | Несколько раз замените фото/видео после Apply/Cancel/export. Не должно быть поздних скачиваний, потерянных правок нового media, зависшего progress, пропавшего canvas или падения вкладки. Это наблюдение стабильности, а не доказательство универсального безопасного memory budget. |

Для положительного AAC доказательства подходят Chrome на Mac или другой браузер, который действительно поддержал конфигурацию. Если автоматический Mac-прогон недоступен, в Chrome вручную экспортируйте обычный 440 Hz клип, клип со смещённым звуком и асимметричный AV-клип с указанной геометрией; сохраните три файла для анализа.

## Как записать результат

Для каждой среды укажите модель устройства, версию ОС/браузера, build URL/revision, название исходного файла и результат каждой строки: **PASS**, **FAIL**, **UNSUPPORTED** или **UNTESTED**. Unsupported считается корректной обработкой ограничений только при явном сообщении/согласии, и не означает, что сохранение звука было проверено.

Переименуйте сохранённые файлы по среде, например `mac-chrome-av.mp4`, `mac-safari-av.mp4`, `iphone-safari-av.mp4`, `android-chrome-av.mp4`. Сохраните точный текст ошибки и короткую запись, если поведение отличается от ожидаемого.

Issues закрываются после анализа реальных результатов. Production остаётся без публикации до отдельного решения владельца.
